# Iteration 0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a phone-friendly browser prototype with exploration, one battle, and local Continue saves.

**Architecture:** Plain TypeScript owns map rules, combat rules, validated checkpoints, and session transitions. Phaser renders the game; semantic HTML supplies menus, status, and touch controls. Vite builds a static GitHub Pages site.

**Tech Stack:** TypeScript, Phaser, Vite, npm, Vitest, Playwright, GitHub Actions/Pages.

**Spec:** `docs/superpowers/specs/2026-11-16-iteration-0-design.md` (read alongside this plan).

## Global Constraints

- Browser-first, single-player, portrait-first with usable landscape layout.
- No backend, accounts, database, multiplayer, React, or cloud saves.
- No offline/PWA installation requirement in Iteration 0.
- Original placeholder graphics and names; no Final Fantasy assets or branding.
- No app scaffolding or implementation as part of this planning task.

The final constraint applies to writing this plan; executing an approved plan authorizes scaffolding. Exact gameplay values and save semantics below come from the proposed defaults in the spec and must be reviewed before implementation.

## Review Focus

1. Repeated taps during a turn must produce one action, not several (Tasks 3/5).
2. Interrupted input and background/resume must not move the hero unexpectedly (Tasks 2/5).
3. Corrupt saves, unknown versions, and storage failures must preserve a playable experience (Task 4).
4. Small or rotated screens must keep controls visible and avoid horizontal scrolling (Tasks 1/5).
5. Hosting at `/SimpleRpg/` must load assets and allow refresh at the deployed URL (Task 6).

## File map and shared interfaces

Paths are relative to the verified repository root. All files below are new except the existing README.

- Root: `package.json`, `package-lock.json`, `tsconfig.json`, `vite.config.ts`, `.gitignore`, `.nvmrc`, `index.html`, `playwright.config.ts`.
- `src/game/types.ts`: shared `Position`, `Direction`, `Checkpoint`, `BattleState`, `GameState`, `Action` types.
- `src/game/world.ts`: immutable map and encounter definition, walkability, movement rules.
- `src/game/battle.ts`: pure battle turn resolution.
- `src/game/session.ts`: session creation and transitions, without DOM or storage.
- `src/game/save.ts`: runtime validation and guarded storage adapter.
- `src/main.ts`: startup, event wiring, persistence, scene/menu synchronization.
- `src/view/GameScene.ts`: render world and battle with generated textures.
- `src/view/ui.ts`, `src/style.css`: HTML menus, status, controls, responsive layout.
- `tests/world.test.ts`, `tests/battle.test.ts`, `tests/session.test.ts`, `tests/save.test.ts`: rule tests.
- `e2e/game.spec.ts`: browser interactions and responsive checks.
- `.github/workflows/ci.yml`, `.github/workflows/pages.yml`: checks and deployment.

Define shared types once: `Position = { x: number; y: number }`; `Direction = 'up' | 'down' | 'left' | 'right'`; `Checkpoint = { version: 1; position: Position; hp: number; completedEncounterIds: string[] }`. World constants include `MAX_HP=12` and encounter ID `slime-1`.

Use a discriminated `GameState`: title, exploring (checkpoint), battle (checkpoint, safe return position, battle state), victory (checkpoint), or defeat (last checkpoint). `BattleState = { heroHp: number; enemyHp: number; result: 'active' | 'victory' | 'defeat' | 'escaped' }`. `Action` includes newGame, continue(checkpoint), move(direction), attack, run, acknowledgeVictory, restart. Only the session accepts these actions; view code does not independently change HP or position.
